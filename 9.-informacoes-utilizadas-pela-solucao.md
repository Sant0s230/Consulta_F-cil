# 9. Informações utilizadas pela solução

| Tabela      | Informação                            | Finalidade                                           |
| ----------- | ------------------------------------- | ---------------------------------------------------- |
| `profiles`  | Nome                                  | Identificar o perfil do usuário                      |
| `profiles`  | Telefone e e-mail de aviso            | Configurar formas de contato                         |
| `profiles`  | Preferências de aviso e antecedência  | Definir os avisos desejados                          |
| `profiles`  | Nome e celular do acompanhante        | Prepara uma mensagem para WhatsApp                   |
| `consultas` | Profissional e especialidade          | Identificar o atendimento                            |
| `consultas` | Tipo: consulta, exame ou procedimento | Classificar o compromisso                            |
| `consultas` | Data e horário                        | Organizar a agenda                                   |
| `consultas` | Local e exigências                    | Informar onde será a consulta e o que levar ou fazer |
| `consultas` | Status                                | Indicar se está agendada, realizada ou cancelada     |

As preferências de acessibilidade ficam salvas no aparelho. As preferências de aviso e os dados do acompanhante ficam associados à conta. A documentação do sistema descreve regras para que cada pessoa acesse somente os próprios registros.

#### Registro histórico do primeiro protótipo

O primeiro protótipo armazenava os dados no navegador e permitia cadastrar e editar consultas. Em outra etapa inicial, o armazenamento foi migrado para Lovable Cloud e PostgreSQL, com perfis, contas e consultas associadas ao usuário. Não apresentar o armazenamento local e o banco atual como se fossem a mesma arquitetura.

# 3. Funcionalidades

## Principais Funcionalidades

**Funcionalidades implementadas:**\
• Cadastrar uma nova consulta (profissional, especialidade, data, hora, local e exigências);\
• Listar todas as consultas, ordenadas da mais próxima para a mais distante;\
• Editar os dados de uma consulta já cadastrada;\
• Excluir uma consulta, com confirmação antes de remover;\
• Atualizar rapidamente o status de uma consulta (agendada, realizada ou cancelada);\
• Destacar em um card a próxima consulta futura do usuário;\
•&#x20;Identificar visualmente consultas atrasadas (data já passada e ainda "agendada").

\
**Possíveis evoluções futuras (fora do escopo atual):**\
• Cadastro separado de "Profissionais" (nome, telefone, endereço), reaproveitado em várias\
consultas;\
• Filtros de busca por profissional, especialidade ou status;\
• Envio automático de lembretes por e-mail antes da consulta;\
• Visão em formato de calendário;\
• Autenticação de usuários, permitindo múltiplas pessoas usando o mesmo sistema.



## Descrição da Solução

O sistema é uma aplicação web desenvolvida em **Python (Flask)**, com banco de dados **SQLite** e\
interface estilizada com **Bootstrap**. Ele permite que o usuário cadastre, visualize, edite, exclua e\
atualize o status de suas consultas em um único painel, com destaque visual automático para a\
próxima consulta agendada e para consultas que já passaram da data sem terem sido marcadas como&#x20;realizadas ("atrasadas").

\
O projeto foi desenhado como um **MVP (Produto Mínimo Viável):** um conjunto essencial e bem\
definido de funcionalidades, evitando recursos que aumentariam a complexidade sem agregar valor\
imediato ao problema identificado.<br>

Um protótipo de interface também foi construído na plataforma Lovable (ferramenta de IA generativa\
para prototipação de interfaces web), utilizado como apoio ao processo de definição visual da soluçãoantes/durante a implementação em Flask.

| Camadas        | Tecnologia              | Papel no projeto                                                                |
| -------------- | ----------------------- | ------------------------------------------------------------------------------- |
| Back-end       | Python + Flask          | <p>Recebe requisições, executa a lógica de negócio e retorna as<br>páginas</p> |
| Banco de dados | SQLite                  | Armazena as consultas em um único arquivo (consultas.db)                        |
| Front-end      | HTML + Jinja2           | Estrutura das páginas, com dados dinâmicos vindos do Flask                      |
| Estilização    | Bootstrap (CDN)         | <p>Layout responsivo e visual profissional sem CSS<br>customizado</p>          |
| Prototipação   | Lovable (IA generativa) | Apoio na prototipação inicial da interface                                      |

**Justificativa da escolha:** Essa combinação foi escolhida por ser leve, bem documentada e adequada\
para quem está começando a programar. O SQLite não exige instalação de servidor de banco de\
dados dedicado, e o Flask tem uma curva de aprendizado suave em comparação a outros frameworks&#x20;web, favorecendo facilidade de utilização, baixo custo (todas as tecnologias são gratuitas e de código&#x20;aberto) e adequação ao problema, que não exige alta escalabilidade em sua fase de MVP.

## Informações Utilizadas pela Solução

Todas as consultas são armazenadas em uma única tabela (consultas) no banco SQLite, criada\
automaticamente pela função init\_db() na primeira execução do sistema.

| Campo         | Tipo                 | Descrição                                  |
| ------------- | -------------------- | ------------------------------------------ |
| id            | Inteiro (automático) | Identificador único da consulta            |
| profissional  | Texto                | Nome do médico ou profissional responsável |
| especialidade | Texto                | Ex.: Cardiologista, Dentista, Psicólogo    |
| data          | Texto (AAAA-MM-DD)   | Data em que a consulta ocorrerá            |
| hora          | Texto (HH:MM)        | Horário da consulta                        |
| local         | Texto                | Endereço ou nome da clínica/consultório    |
| exigências    | Texto livre          | Ex.: jejum, levar exame, levar documento   |
| status        | Texto                | "agendada", "realizada" ou "cancelada"     |

Não há, na versão atual, cadastro de dados de identificação do próprio usuário (login, CPF, e-mail),\
nem coleta de dados de terceiros além das informações que o próprio usuário decide registrar sobre\
seus compromissos.
